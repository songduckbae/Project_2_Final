# 🚀 MSA 마이그레이션 및 비용 비교 프로젝트 (ACORN)

이 프로젝트는 **EC2 기반 MSA 서비스를 EKS로 마이그레이션**하여 **비용 최적화**와 **운영 효율성**을 개선하는 것을 목표로 합니다.

> **핵심 성과**: EC2 대비 EKS 환경에서 **월 $166 (약 29%) 비용 절감** 달성

---

## 📝 프로젝트 개요

### 배경
- 트래픽이 많고 안정적으로 운영해야 하는 대학 시스템 운영 중
- 3개의 서로 다른 특성의 서비스 가정
  - **중앙 인증** 서비스
  - **수강신청** 서비스  
  - **공지** 서비스

### 목표
- MSA로 운영하던 서비스를 EC2에서 EKS로 마이그레이션하여 비용 최적화
- **무중단 마이그레이션** 구현
- **부하테스트**를 통한 성능 및 비용 비교 분석

---

## 🏗️ 아키텍처 비교

### EC2 환경
- **구성**: 각 서비스별 독립적인 Auto Scaling Group
- **인스턴스**: m7g.large (2vCPU, 8GB) 
- **로드밸런서**: 서비스별 독립 ALB 3개
- **장점**: 초기 구축이 쉽고 작은 인프라에서 관리 용이, 완전한 격리 환경
- **단점**: 인프라 확장 시 관리 복잡, 리소스 낭비, ASG 모니터링 주기 느림

### EKS 환경
- **구성**: EKS 클러스터 기반 Pod 배포
- **노드**: m7g.xlarge (4vCPU, 16GB) 기반
- **로드밸런서**: Ingress 기반 통합 ALB
- **장점**: HPA와 Karpenter로 빠른 확장, Pod 단위 효율적 리소스 사용
- **단점**: 운영 초기 어려움, 클러스터 비용 추가 발생

## 🔄 무중단 마이그레이션

### 마이그레이션 흐름
1. **EKS 환경 구축** 및 서비스 배포
2. **API Gateway** 기반 트래픽 라우팅 설정
3. **점진적 트래픽 전환**: EC2 → EKS
4. 안정성 확인 후 완전 전환

```
[API Gateway] 
     ↓
┌─────────────────┐    ┌─────────────────┐
│   EC2 환경      │ →  │   EKS 환경      │
│ (기존 서비스)    │    │ (새로운 서비스)   │
└─────────────────┘    └─────────────────┘
```

## 📊 부하테스트

### 테스트 환경
- **도구**: Hey 명령어 사용
- **부하 조건**: 
  ```bash
  hey -n 600000 -c 3000 -q 3000 http(s)://{도메인}/notice/
  ```

### 테스트 결과
- **EC2**: ASG 기반 확장으로 인스턴스 증가 (느린 반응)
- **EKS**: Karpenter 통해 빠른 노드 확장 및 Pod 스케일링
- **성능**: EKS가 더 빠른 오토스케일링으로 응답성 우수

## 💰 비용 분석

### 시나리오 가정
- 부하가 없는 평소: 적은 수준의 vCPU 사용
- 각 서비스 부하 발생 시간: 한 달에 10% 시간
- 트래픽 몰릴 때: 서비스당 약 7 vCPU까지 사용
- 패킷 크기: 요청당 평균 2KB, 평균 2회 내부 요청

### 추가 고려사항
- 서비스 종류와 로드밸런서가 많을수록 EKS가 더 저렴
- 스팟 인스턴스 활용 시 EKS에서 더욱 유연하고 저렴한 관리 가능
- 캐시, 메시지큐 등 클러스터를 쿠버네티스 리소스로 관리 가능
